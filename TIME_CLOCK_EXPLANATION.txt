1. ARQUITECTURA GENERAL
================================================================================

El Time Clock está compuesto por:

1. PANTALLA PRINCIPAL: TimeClockScreen.js
   - Interfaz de usuario completa
   - Manejo de estado local
   - Interacción con el usuario
   - Accesible desde Teams → Time Clock

2. RESUMEN EN TEAMS: TeamsScreen.js
   - Sección de resumen del Time Clock
   - Muestra estado actual (Clocked In/Out)
   - Muestra horas de hoy y esta semana
   - Badge "IN" cuando está clocked in
   - Navegación a pantalla completa

3. SERVICIO: shiftsService.js
   - Lógica de negocio
   - Comunicación con Supabase
   - Subida de fotos a Storage

4. BASE DE DATOS: Tabla "shifts"
   - Almacena registros de clock in/out
   - Campos: clock_in, clock_out, location, duration
   - NUEVOS: latitude, longitude, photo_url

5. STORAGE: Supabase Storage bucket "team-files"
   - Almacena fotos capturadas
   - Estructura: shift-photos/{userId}/{timestamp}.{ext}

NOTA DE DISEÑO:
El Time Clock está integrado dentro de Teams porque:
- Es más relevante en contexto de equipo/empresa
- No todos los usuarios individuales necesitan Time Clock
- Libera espacio en la navegación principal
- Mantiene consistencia con otras features de equipo

================================================================================
2. FLUJO DE CLOCK IN (CHECK-IN)
================================================================================

PASO 1: Usuario presiona botón "Clock In"
   └─> Se deshabilita el botón
   └─> Se muestra loading state

PASO 2: Obtener Ubicación GPS
   └─> Solicitar permisos de ubicación (expo-location)
   └─> Si permisos denegados: continuar sin ubicación (no bloquea)
   └─> Obtener coordenadas: latitude, longitude
   └─> Manejar errores gracefully

PASO 3: Capturar Foto (solo en móvil)
   └─> Solicitar permisos de cámara (expo-image-picker)
   └─> Si permisos denegados: continuar sin foto (no bloquea)
   └─> Abrir cámara nativa
   └─> Usuario puede cancelar (retorna null)
   └─> Si captura: obtener URI de la foto
   └─> Detectar tipo MIME (JPEG, PNG, HEIC, HEIF)

PASO 4: Subir Foto a Storage (si se capturó)
   └─> Detectar formato de imagen desde MIME type o URI
   └─> Crear nombre de archivo: shift-photos/{userId}/{timestamp}.{ext}
   └─> Convertir URI a Blob
   └─> Subir a Supabase Storage bucket "team-files"
   └─> Obtener URL pública de la foto
   └─> Si falla: continuar sin foto (no bloquea clock in)

PASO 5: Crear Registro en Base de Datos
   └─> Validar usuario autenticado
   └─> Verificar que no haya turno activo
   └─> Insertar en tabla "shifts":
      * user_id
      * clock_in (timestamp actual)
      * location (seleccionada por usuario)
      * latitude (si se obtuvo)
      * longitude (si se obtuvo)
      * photo_url (si se subió foto)
   └─> Retornar shift creado

PASO 6: Actualizar UI
   └─> Mostrar estado "Clocked In"
   └─> Mostrar tiempo de check-in
   └─> Iniciar contador de tiempo transcurrido
   └─> Guardar estado en AsyncStorage (backup local)
   └─> Recargar historial de shifts

================================================================================
3. FLUJO DE CLOCK OUT (CHECK-OUT)
================================================================================

PASO 1: Usuario presiona botón "Clock Out"
   └─> Validar que hay turno activo
   └─> Se deshabilita el botón
   └─> Se muestra loading state

PASO 2: Calcular Duración
   └─> Obtener turno activo de BD
   └─> Calcular diferencia: clock_out - clock_in
   └─> Convertir a horas decimales (ej: 8.5 horas)

PASO 3: Actualizar Registro en BD
   └─> Actualizar turno con:
      * clock_out (timestamp actual)
      * duration (horas calculadas)
   └─> Retornar shift actualizado

PASO 4: Actualizar UI
   └─> Mostrar estado "Clocked Out"
   └─> Limpiar contador de tiempo
   └─> Limpiar AsyncStorage
   └─> Recargar historial de shifts
   └─> Actualizar resumen semanal de horas

4. DETALLES TÉCNICOS
================================================================================

4.1 GEOLOCALIZACIÓN
-------------------
Librería: expo-location

Web:
- Usa Geolocation API del navegador
- Solicita permisos automáticamente
- Precisión: Balanced (balance entre precisión y batería)

Móvil (iOS/Android):
- Usa GPS nativo del dispositivo
- Precisión: Balanced
- Maneja permisos con requestForegroundPermissionsAsync()

Manejo de Errores:
- Si permisos denegados: retorna null, null (no bloquea)
- Si GPS no disponible: retorna null, null (no bloquea)
- Muestra alerta informativa pero permite continuar

4.2 CAPTURA DE FOTO
-------------------
Librería: expo-image-picker

Móvil (iOS/Android):
- Abre cámara nativa del dispositivo
- Permite editar/recortar antes de confirmar
- Aspect ratio: 4:3
- Calidad: 0.8 (80% - balance calidad/tamaño)

Formatos Soportados:
- JPEG (Android, Web)
- PNG (todos)
- HEIC/HEIF (iOS nativo - más eficiente)

Detección de Formato:
1. Intenta obtener mimeType del asset
2. Si no está disponible, detecta desde URI
3. Usa el tipo correcto al subir a Storage

Web:
- Actualmente no implementado (solo móvil)
- Puede agregarse con webcam API o input file

4.3 SUBIDA DE FOTOS
--------------------
Proceso:
1. Detectar formato (JPEG, PNG, HEIC, HEIF)
2. Crear nombre único: shift-photos/{userId}/{timestamp}.{ext}
3. Convertir URI a Blob:
   - Web: fetch(URI) -> blob
   - Móvil: fetch(URI local) -> blob
4. Subir a Supabase Storage:
   - Bucket: "team-files"
   - Content-Type según formato detectado
5. Obtener URL pública
6. Guardar URL en campo photo_url de shifts

Manejo de Errores:
- Si bucket no existe: retorna null (no bloquea)
- Si falla subida: retorna null (no bloquea)
- Logs de error para debugging

4.4 BASE DE DATOS
-----------------
Tabla: shifts

Campos Originales:
- id (BIGSERIAL)
- user_id (UUID)
- clock_in (TIMESTAMP)
- clock_out (TIMESTAMP, nullable)
- location (TEXT)
- duration (DECIMAL)

Campos Nuevos (migration):
- latitude (DECIMAL(10, 8), nullable)
- longitude (DECIMAL(11, 8), nullable)
- photo_url (TEXT, nullable)

Políticas RLS:
- Usuarios solo pueden ver/crear sus propios shifts
- Verificación de autenticación en cada operación

4.5 ALMACENAMIENTO LOCAL
------------------------
AsyncStorage:
- Guarda estado de clock in (backup)
- Permite recuperar estado si app se cierra
- Clave: '@teamlink_clock_state'
- Datos: { isClockedIn, clockInTime, location }

Sincronización:
- Al iniciar app, verifica turno activo en BD
- Si hay turno activo en BD, restaura estado local
- Si no hay turno activo, limpia estado local

5. INTERFAZ DE USUARIO
================================================================================

5.1 ESTADOS VISUALES
--------------------
Clock In (No trabajando):
- Botón verde "Clock In"
- Selector de ubicación visible
- Reloj mostrando hora actual
- Sin contador de tiempo

Clock Out (Trabajando):
- Botón rojo "Clock Out"
- Muestra hora de check-in
- Contador de tiempo transcurrido (actualiza cada segundo)
- Selector de ubicación oculto

Loading States:
- Botón deshabilitado con spinner
- Mensajes: "Getting location...", "Capturing photo..."

5.2 HISTORIAL DE SHIFTS
------------------------
Muestra últimos 5 shifts completados:
- Fecha (hoy, ayer, o fecha completa)
- Horario (clock in - clock out)
- Ubicación con icono
- Coordenadas GPS (si disponibles)
- Foto (si se capturó)
- Duración en horas

5.3 RESUMEN SEMANAL
-------------------
- Total de horas trabajadas esta semana
- Calculado desde domingo de la semana actual
- Solo incluye shifts completados (con clock_out)

5.4 TEMAS Y ESTILOS
-------------------
- Integrado con sistema de temas de la app
- Soporta Light, Dark, y temas Pastel
- Colores dinámicos según tema seleccionado
- Sombras y bordes redondeados
- Responsive para web y móvil

================================================================================
6. CASOS EDGE Y MANEJO DE ERRORES
================================================================================

6.1 PERMISOS DENEGADOS
----------------------
Ubicación:
- Muestra alerta informativa
- Permite continuar sin ubicación
- Clock in se guarda sin coordenadas

Cámara:
- Muestra alerta informativa
- Permite continuar sin foto
- Clock in se guarda sin foto

6.2 TURNO ACTIVO EXISTENTE
--------------------------
Al intentar clock in:
- Verifica si hay turno activo (sin clock_out)
- Si existe: muestra error
- Usuario debe hacer clock out primero

6.3 ERRORES DE RED
------------------
Clock In:
- Si falla: muestra error, no cambia estado
- Usuario puede reintentar

Clock Out:
- Si falla: muestra error, mantiene estado "clocked in"
- Usuario puede reintentar

Subida de Foto:
- Si falla: continúa sin foto
- No bloquea el clock in
- Logs de error para debugging

6.4 SINCRONIZACIÓN
------------------
Al iniciar app:
- Verifica turno activo en BD
- Si hay turno activo: restaura estado
- Si no hay: limpia estado local
- Previene estados inconsistentes

     * image/heic

8. FLUJO DE DATOS COMPLETO

EJEMPLO: Clock In con ubicación y foto

1. Usuario → TimeClockScreen
   └─> Presiona "Clock In"
   └─> Selecciona ubicación: "Main Office"

   └─> Solicita permisos
   └─> Obtiene: { latitude: 40.7128, longitude: -74.0060 }

3. TimeClockScreen → capturePhoto()
   └─> Solicita permisos cámara
   └─> Captura foto
   └─> Retorna: photoUri, mimeType: "image/heic"

4. TimeClockScreen → shiftsService.uploadPhoto()
   └─> Detecta formato: HEIC
   └─> Crea nombre: shift-photos/{userId}/1234567890.heic
   └─> Convierte a Blob
   └─> Sube a Storage
   └─> Retorna: "https://...supabase.co/storage/v1/object/public/team-files/..."

5. TimeClockScreen → shiftsService.clockIn()
   └─> Parámetros:
      * userId
      * location: "Main Office"
      * latitude: 40.7128
      * longitude: -74.0060
      * photoUrl: "https://..."
   └─> Inserta en BD
   └─> Retorna: { success: true, shift: {...} }

6. TimeClockScreen → Actualiza UI
   └─> Muestra "Clocked In"
   └─> Inicia contador
   └─> Guarda en AsyncStorage

7. BD → Almacena:
   {
     id: 123,
     user_id: "uuid...",
     clock_in: "2025-01-25T10:00:00Z",
     location: "Main Office",
     latitude: 40.7128,
     longitude: -74.0060,
     photo_url: "https://...",
     clock_out: null,
     duration: null
